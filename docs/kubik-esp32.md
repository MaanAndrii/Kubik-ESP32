# Kubik ESP32: прототип для Waveshare ESP32-S3 Touch AMOLED 2.16

## Архітектура та межі

DeskOne залишається власником персонажа, розкладу, погоди, дозволів та матриці
аксесуарів. Опціональний LAN-сервіс публікує реальний SceneFrame після
SceneDirector, до підміни діагностичним preview. ESP32 показує мінімальний
геометричний персонаж із морганням, станом сну, локацією й емоцією.
Предмет у руках і носимі аксесуари наразі показуються текстом; прозорість предмета
відповідає held_visibility. Це не повний порт ілюстрованого рендера DeskOne.

Сенсор надсилає тільки touch, не змінює розклад або аксесуари безпосередньо.
Зміни персонажа виконуються основним потоком застосунку. Сон залишається
визначеним розкладом, DND блокує звичайну взаємодію. Сигнали та їхній дозвіл
визначає чинний QuietPolicy і SceneDirector.

## DeskOne

Спершу встановіть bridge в DeskOne за docs/deskone-integration.md.
Python 3.12, залежності й запуск — як у README DeskOne. У PowerShell:
```powershell
$env:KUBIK_BRIDGE_ENABLE = "1"
$env:KUBIK_BRIDGE_TOKEN = "<власний випадковий токен довжиною мінімум 24 символи>"
$env:KUBIK_BRIDGE_HOST = "0.0.0.0"
$env:KUBIK_BRIDGE_PORT = "8765"
python app.py
```
Без ENABLE=1 мережевий сервіс не запускається. Дозвольте в Windows Firewall
вхідний TCP 8765 тільки для приватної локальної мережі; плата й ПК мають бути
в одній Wi-Fi/LAN мережі. Використовуйте фактичну IPv4-адресу ПК, не localhost.
Прототип використовує HTTP з Bearer-токеном у довіреній локальній мережі.
Трафік не шифрується; не відкривайте порт в інтернет.
Неправильний або короткий токен зупиняє запуск увімкненого bridge з помилкою.

## Збірка й прошивка

Встановіть ESP-IDF **5.5.5** з ESP-IDF Tools Installer для Windows або
офіційним інсталятором Espressif і відкрийте ESP-IDF terminal.
```text
cd firmware/kubik-esp32
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p COM5 flash monitor
```
У menuconfig → Kubik companion задайте Wi-Fi SSID, пароль, URL
http://<IPv4-ПК>:8765 без кінцевого / та той самий токен. COM5 замініть
фактичним портом USB плати. Вихід із monitor: Ctrl+].
Компонентний менеджер завантажує Waveshare BSP 2.0.1 та LVGL 9.3.0.
Конфігурація — 16 MB flash, Octal PSRAM; QSPI AMOLED і CST9220
ініціалізує офіційний BSP. Якщо USB-порт не з'являється, використайте
процедуру входу в download mode із документації Waveshare для цієї плати.

CI збирає прошивку з порожніми Wi-Fi SSID/паролем/токеном. Артефакт CI
перевіряє компіляцію, але для підключення потрібна власна конфігурація й збірка.
Не комітьте sdkconfig, Wi-Fi пароль або токен.

## Протокол v1

- GET /v1/state: Authorization: Bearer <token>. До першого кадру:
  {"version":1,"ready":false}. Потім emotion, mode, sleeping, location,
  held, visibility, wearables, contexts, timer_progress.
- POST /v1/touch: JSON {"id":"<boot-id>-<sequence>","action":"touch"}.
  До 256 байтів. Черга 32 подій, повтори останніх 128 ID не застосовуються вдруге.
- 401: токен; 400: некоректна подія; 404: шлях; 503: черга заповнена.
- ESP32 опитує стан кожні 500 мс, таймаут запиту 1500 мс.
  Через 5 секунд без валідного стану показує Offline і прибирає аксесуари.
  Дотики мають debounce 300 мс і обмежену чергу. Доставка best effort:
  невдалі запити не повторюються; під час втрати Wi-Fi черга очищується.
  Токен/адреса виправляються через menuconfig і повторну прошивку.

## Перевірка

Автоматизація: .github/workflows/ci.yml перевіряє авторизацію,
початковий стан, точну передачу вирішених аксесуарів, дедуплікацію,
обмеження черги, синтаксис Python і компіляцію ESP32-S3. Тести
настільного застосунку залишаються в DeskOne; інтеграція описана в
docs/deskone-integration.md.
Результат конкретного запуску CI слід перевіряти за commit SHA.

Фізичний пристрій потрібен для перевірки:
1. Завантаження, живлення, PSRAM, AMOLED, орієнтації й яскравості.
2. Сенсора: один дотик — одна реакція; утримання не створює потік подій.
3. Реального Wi-Fi, відновлення після вимкнення роутера/DeskOne та Offline.
4. WORK/OFFICE, ACTIVE/STREET, SLEEP/HOME, DND, сигналів таймера/будильника.
5. Дозволів аксесуарів, видимості переходів і плавності анімації.
6. Тривалої стабільності, температури, енергоспоживання й батарейного режиму.

Фізична валідація не виконана. Не заявляти працездатність на платі тільки
на підставі успішної компіляції.
